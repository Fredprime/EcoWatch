# 15 — Maintenance and Future Expansion

**Status:** Long-term operating principles; responsible organisation and funding remain open.

## 1. Purpose

EcoWatch will only have lasting value if someone can operate, maintain, review and improve it after the initial project or hackathon.

## 2. Operational ownership

Before a live pilot, identify:
- Product owner.
- Technical maintainer.
- Data steward.
- Environmental/scientific reviewer.
- Case-review lead.
- Security and privacy contact.
- Partner responsible for field response, if applicable.

One person may hold multiple roles in a small pilot, but responsibilities must still be explicit.

## 3. Routine maintenance

- Review application and server errors.
- Monitor database and file storage.
- Check backup completion and restore capability.
- Review failed imports and queued jobs.
- Patch dependencies.
- Review user access.
- Respond to data correction requests.
- Check external data source availability and licence changes.
- Review model performance and false alarms.
- Update documentation after changes.

## 4. Data stewardship

Assign responsibility for dataset metadata, quality notes, versioning, access rights, retention and correction. Imported datasets should not become untraceable after repeated updates.

## 5. Model and analytical maintenance

Monitor:
- Changes in satellite sensors or data products.
- Seasonal variation.
- Model performance across locations.
- New sources and missing data.
- Threshold validity.
- Drift and changes in environmental context.

Revalidate methods before expanding to a new region or environmental problem.

## 6. Future expansion candidates

Potential future areas include:
- More watersheds and districts.
- Additional water and soil indicators.
- Biodiversity and habitat monitoring.
- Flooding, erosion and waste-management use cases.
- Additional institutional datasets.
- Community language support.
- Offline-first reporting.
- More advanced event clustering and predictive analysis.
- Partner-facing data exchange.
- Public environmental history and recovery reporting.

Each expansion requires a use case, data, stakeholder support, cost assessment and validation plan.

## 7. Sustainability

Potential operating models may include institutional partnerships, research collaborations, grants, public-sector support or a combination. No funding or partnership is assumed. The project should avoid a design that can only operate if one temporary sponsor or individual remains available.

## 8. Exit and portability

Maintain documented exports, schema definitions, media references, source metadata and operational documentation. If a provider or partner relationship ends, the project should have a practical way to retrieve its data and continue operating.

## 9. Annual review

At least periodically, review whether EcoWatch is still solving the intended problem, whether users trust it, whether evidence quality is improving, whether interventions are being tracked and whether operating costs are sustainable.
